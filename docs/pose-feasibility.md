# 幻真画室｜姿势库技术预研与可行性

> 2026-11-10。资料研究与方案评估，**不是实测报告**。公开文档仅讨论通用人体姿势、动画和工程接口。原始第三方模型与私人素材不进入公开仓库。

## 1. 研究问题与结论

目标：把图片、现有 FBX/BVH/GLB/Blend 动作或手动调整后的 3D 姿势保存为**可复用姿势卡**，用于不同身材的成年人体模型；保持原有摄影/透视自由度，未来供 3D 动画积木和 2D 结构参考使用。

**判断：分阶段可行。**
- 已有 Rig 且骨架一致：保存、浏览、应用姿势难度低。Blender 4.5 LTS 官方 Pose Library 基于 Asset Browser，姿势资产是含一帧动画数据的 Action，可有缩略图、目录、混合应用和局部骨骼应用。
- 不同骨架：可通过开源重定向插件解决大部分映射，但需要统一静止姿势、比例和坐标系；不能承诺自动一次成功。
- 不同体型：单纯复制旋转不能保证手脚接触和身体无穿模；需要 IK、支撑点锁定、碰撞检测和局部蒙皮修正。
- 从视频/图片估计姿势：可生成**候选姿势**，不等于唯一准确 3D 重建。动漫透视、遮挡、非真实比例和多人物场景是高风险。
- 这次仅核查资料、仓库接口与素材目录线索；**没有在用户 Windows 电脑上安装或跑过插件，没有用其实际人体模型做兼容性验证**。

## 2. 资料与开源候选（按职责）

### A. 官方基础：Blender Pose Library（优先）

文档：https://docs.blender.org/manual/zh-hans/4.5/animation/armatures/posing/editing/pose_library.html

- Action 中保存单帧姿势；Asset Browser 提供名称、缩略图、目录、过滤、直接应用、混合与翻转。
- 可将已有动画中的某一帧转成姿势资产。
- **推荐**：把 Blender 作为姿势资产的权威编辑/存储后端；幻真画室保存索引、缩略图、用户标签和适配信息。不要重新发明 Blender 的完整姿势编辑器。
- 局限：依赖可用骨架；跨不兼容骨架需要重定向；原生姿势资产并不自动解决不同身材的碰撞。

### B. 开源骨架重定向

1. **Mwni/blender-animation-retargeting**
   - https://github.com/Mwni/blender-animation-retargeting
   - 项目明确提供源/目标骨架映射、Rest Pose 对齐、手脚 IK 位置修正和 Bake。
   - 适合做最小验证的透明基线：先人工映射一个模型，再检查是否可自动化。
   - 风险：需确认 Blender 当前版本、维护情况和许可证；手工映射仍有成本。

2. **KBS-DEV Retarget（Blender 官方扩展站）**
   - https://extensions.blender.org/add-ons/retarget/
   - 文档列出 Mixamo、Unreal、VRoid、MMD、Daz 等预设、Rigify 转换、动作管理和烘焙；标明 Blender 5.0+、GPL-3.0-or-later。
   - 适合多来源骨架和未来动作资产管理。需注意版本要求，不能在未确认 Blender 版本时直接安装。

3. **MondRubberduck/Bulletproof-Retarget**
   - https://github.com/MondRubberduck/Bulletproof-Retarget
   - 自述支持 Blender 5.0+，多种常见骨架自动识别，映射人体和手指骨骼。
   - 可作为自动化候选；项目宣称的“一键”需要用用户真实模型验证，尤其是非标准骨架。

4. **Rokoko 官方 Blender 插件**
   - https://github.com/Rokoko/rokoko-studio-live-blender
   - https://support.rokoko.com/hc/en-us/articles/4410463481489-Retarget-an-animation-in-Blender
   - 具备重定向和动作流接口，官方说明重定向不要求付费订阅；直播和额外功能的环境依赖需另查。
   - 作为成熟对照基线，不应因品牌名就默认是最佳选择。

**选择策略**：优先官方 Pose Library + 一个实际兼容的重定向插件。不要一次性把所有插件装进用户 Blender；先锁定 Blender 版本，再比较同一测试动作的结果、安装成本、失败率和可批处理性。

### C. 图片/视频到候选姿势（后续）

- https://github.com/s0ck3t/VideoIntoBlenderModel
- 项目自述支持单张照片或单目视频、MediaPipe 关键点、IK、足部锁定、导出 GLB、Blender 4.2+。其 README 中关于速度、精度、授权与自动适配的性能宣称**未经本项目独立复测**。
- 优先用清晰、无遮挡、真人比例的公开样本验证；动漫图片、强透视和遮挡图应只给“候选姿势 + 人工确认”，不能默认自动得到准确关节深度。
- 多张同角色图片可帮助消除部分歧义，但镜头参数不明时仍不能唯一恢复 3D。

## 4. 与现有仓库的适配

3D 仓库：https://github.com/Xiatiantian1997/Fantasy-Studio-3D

其 README 明确现有的是设计、导出 schema、示例和校验脚本；尚无验收通过的全身人体模型、五姿势或真实 Blender 导出。故当前最大的工程依赖是**先选出并验证一份可绑定的人体母版**，不是继续寻找更多姿势包。

现有接口：`docs/interface-v0.1.md`，定义单帧 `manifest.json`、RGB、Depth、Normal、Pose；含 `subject_id`、`pose_id` 和相机一致性。姿势库应引用这些 ID，不重新发明相机/深度坐标格式。

建议新增独立的姿势资源索引（规划，不是已部署）：
- `pose_id`：稳定标识；
- `source`：原始文件引用、授权和提取方法；
- `rig_profile`：标准骨架版本与 rest pose；
- `pose_asset`：Blender Action / .blend 资产位置；
- `preview`：标准镜头的 PNG/WebP；
- `contacts`：手、脚、膝等支撑点及锁定规则；
- `tags`：站、坐、跪、俯身、躺卧等；
- `quality`：candidate / user_confirmed / validated；
- `adaptation`：已验证的体型/骨架范围及异常。

UI 不必显示这些字段；姿势卡只显示人物白模缩略图、名称和“应用/编辑/收藏”，细节保存在后台。

## 5. 核心技术：跨体型复用

1. **统一标准骨架**：确定骨骼名称、局部轴、根节点、比例、A/T Rest Pose；角色绑定与姿势数据分开。
2. **关节旋转重定向**：在骨架本地坐标下变换，正确处理静止姿势差异与四元数；避免直接复制世界坐标。
3. **体型参数**：形态键改变表面网格后，应同步检查骨骼、蒙皮权重与必要的骨骼定位。身材卡保存完整参数快照，但 UI 不显示全部。
4. **支撑点修正**：手掌、脚底、膝盖等采用 IK 目标，保留地面接触；允许不同体型的骨盆位置自动小幅调整。
5. **碰撞与穿模**：检测手臂-躯干、腿-腹部、衣服-身体等冲突；先做低成本碰撞近似和用户可见的修正提示，不承诺一键解决复杂自碰撞。
6. **保存与回退**：原始姿势资产只读；适配后产生可撤销的新预设，不覆盖原版。

**难点排序**：同骨架姿势保存 < 常见骨架重定向 < 不同体型接触修正 < 任意动漫图片自动精确还原。

## 6. 最小验证矩阵

| 测试 | 输入 | 成功判据 |
|---|---|---|
| T1 姿势保存 | 一个已绑定模型，站姿与跪姿 | 重新打开后骨骼旋转和预览一致 |
| T2 同骨架复用 | 相同骨架不同体型 | 基础姿势保留，关节无明显翻转 |
| T3 支撑点 | 跪姿、俯身支撑 | 手/膝接触地面，不明显漂浮或穿入 |
| T4 跨骨架 | Mixamo/VRM/自有模型中选两种 | 骨骼映射完整，关键关节方向正确 |
| T5 动作抽帧 | FBX/BVH 动画 | 任意选定帧能保存为姿势卡 |
| T6 图片估计 | 清晰单人公开参考图 | 得到可编辑候选姿势，标明不确定性 |
| T7 导出 | 已验证姿势 + 相机 | 与现有 manifest 的 pose_id/相机/深度/法线约定一致 |
| T8 回归 | 体型与镜头分别修改 | 改体型不偷偷改镜头，改镜头不偷偷改姿势 |

首轮只要求 T1–T3；T4–T8 在基础模型可靠后开展。测试应输出前后对比图、失败记录、Blender 版本、插件版本、执行时间和错误日志。

## 7. 资源与性能

- 用户机器 RTX 3060 Ti 8GB：姿势资产管理、骨骼映射和 IK 通常不需要大型生成模型；实时预览可作为目标，但需实测网格复杂度、驱动和插件成本。
- 本地项目与依赖优先 D 盘；原始模型、付费素材、私人参考保留本地，不上传公开 GitHub。
- Google Drive 已知有“人体结构”“10个模型”“动作.zip”“建模视频课”等素材线索，但本轮**未完整下载/解析这些大文件，也未验证其骨架和授权**。不能据此声称已有可直接使用的母版。
- 先清点现有资产，再决定是否需要补充开源样本。不要为了预研批量下载多套大型插件或模型。

## 8. 推荐实施路线

**阶段 0：资产核验**——确定一个连续人体网格、骨架、权重、形态键、许可证与 Blender 版本。若没有合格 Rig，先解决绑定。

**阶段 1：官方姿势库闭环**——站姿/跪姿保存为 Blender Pose Assets，自动生成正面/侧面缩略图；从幻真画室索引调用。可见、可复现。

**阶段 2：三体型适配**——纤细/标准/丰满，先同骨架应用，再加 IK 接触修正；用户能一键切换并对比。

**阶段 3：重定向**——选一个免费兼容插件，导入另一骨架动作，抽帧保存为姿势资产；对失败动作提供手动修正入口。

**阶段 4：图片候选姿势**——评估 VideoIntoBlenderModel 或类似方案，候选结果由用户确认后才加入稳定姿势库。

**阶段 5：动画联动**——把姿势卡作为动作积木起点/终点，加入插值、过渡、接触锁定和局部次级运动；另见 `animation-roadmap.md`。

## 9. 最终产品体验

用户打开 3D 人物 → 选择体型 → 点击姿势缩略图 → 自动应用/必要时修正 → 自由旋转摄影镜头 → 保存姿势卡或导出结构参考。复杂骨架和插件在后台运行。

**最终建议**：以 Blender 官方 Pose Library 为核心，配合经过实测的单一重定向插件；把研发精力集中在体型适配、支撑点 IK、简洁界面与 2D/3D 数据一致性。资料足以支持技术可行性，但真实可用程度必须由用户资产上的 T1–T3 测试决定。
