# 幻真画室｜八类元素设计备忘（2026-11-10）

> **状态：第一轮讨论记录，可随时修改；不是功能完成、最终规范或开发排期。** 只讨论普通图片导入后的元素识别、展示、索引、保存和复用；本轮不展开生图工作流。以用户后续修改为准。现有 2D/3D/总控的开发优先级不变。

## 共通结构
- 一级为**作品组**：一张或多张原始参考图；原图保留、只读、记录来源/权限。
- 二级为八类**元素资源卡**：人物 C、身材 B、姿势 P、衣装 O、表情 E、镜头 K、背景 G、画风 S。每类可有多张卡；同一资源可关联多图。
- 资源卡是用户看到的单位，不等于一张裁切 PNG。可关联原图、缩略图、文字、参数、蒙版、骨骼/3D 引用等；按需保存衍生文件，避免无意义复制高清图。
- 必须区分**原图真实可见部分**、**AI 识别/估计的候选信息**和**AI 推测补全**；不可把单张二维图推测出的隐藏结构、相机或体型冒称精确实测。
- 素材库主要负责浏览、选择、复用和来源追溯；复杂编辑归相应编辑器。共享资源引用而非重复复制。界面优先适配手机，简洁可读。
- 本文示例编号 C001/B001/... 仅表示资源卡，不是必须固定的全局编号方案。

## C 人物
- 此前分支已讨论；不重复定稿细节。人物保存角色身份与稳定外貌特征，区别于可变表情、姿势、衣装。
- 人物卡已有示例；更细的展示/版本规则需以旧分支完整记录复核。

## B 身材
- 此前已讨论：素材库保存最终体型预设及简洁预览（可含正/侧视）；详细体型参数在 3D 编辑器调整，不在素材卡堆滑条。
- 参数可能是推测值，需注明可信度。

## P 姿势
- 姿势与人物、身材、镜头分离，保存参考图、骨骼姿态/基模引用及必要预览；目标可旋转 3D 查看。
- 2D 姿势图不能保证准确恢复隐藏关节；需允许后续人工修正。动作插值/微动画属于未来可选功能。
- 不为每个姿势复制完整高精度人体模型。

## O 衣装（本轮明确决定）
- **整套服装为主卡**；主体、薄纱、袖子、裙摆、饰品等作为卡内可复用部件，细分深度按需决定，暂不强制自动全拆。
- **默认用有正常成年女性体型与基础皮肤质感的「标准女性模特」穿着预览**，不使用容易误解的“中性人形”；真实 3D 试穿是未来目标，不冒称当前可用。
- 同一件衣装的正/侧/背等**多张参考图合并到同一衣装卡**，保留每张图来源与角度。
- 部件可被其他衣装引用，不意外覆盖原卡；保存原图引用、必要蒙版/透明层、属性、来源、可选预览/补全结果。
- 真实提取与 AI 补全分开标记；遮挡部位和背面不等于原图已提供。具体拆解深度、缓存策略留待开发实测。
- 服装的设计/换装功能仍属于后续项目，不因此改变当前里程碑。

## E 表情
- 与人物身份分离；保存面部特写引用、眼眉嘴型/眼神等表情特征、标签及必要参数。
- 相同表情可关联多张参考；可跨人物参考但不得把来源人物的五官身份直接贴过去。动画为未来可选。

## K 镜头
- **作为可复用的镜头预设保存**：原图构图缩略图、角度、透视、取景范围、画幅，以及能可靠提取的参数；缺失参数不编造。
- 不同镜头分别为不同卡，即使来自同一作品组。实际使用时可以自由微调、另存预设，不覆盖原卡。
- 与姿势独立；真实 3D 相机可精确保存参数，单张 2D 图只能估计。**本轮只讨论元素保存，不展开生图**。

## G 背景／场景
- **场景卡包含该场景专属构图**：环境、物件位置、前中后景、视觉中心、人物预留位置、透视引导线、光照氛围等。
- 同一场景多视角/多构图可在同一卡内关联；相似但不同场景不应自动误合并。
- 与 K 区分：K 为通用相机预设；G 为依赖具体场景物件和空间关系的构图。必要时 G 可引用 K。
- 被人物遮挡的背景只能记录可见部分与蒙版；补全须单独标记。

## S 画风（本轮第一版建议）
- **整体风格为主卡，视觉特征为辅**：关联多张原图、风格描述、色板/明暗/饱和度、线条/边缘、光影、材质绘画表现。
- 与人物身份、衣装结构、场景布局分开；可在一张风格卡中关联多张各自贡献不同视觉特征的参考图。
- 自动提取的风格描述属于分析结果，不等于原作者的精确绘画参数。无需为每张图片强制生成新风格卡。

## 未定与后续调整
- 各类卡片最终 UI、去重/自动合并阈值、蒙版与图像缓存大小、模型适配、编号规则、风格混合权重、具体算法均未定。
- 先保留现有开发顺序：验证 2D、统一入口、3D 姿势/相机与接口。素材解析功能当前只是需求备忘，**未实现**。


## 技术路径候选｜2026-11-10（仅备忘，未安装、未实测）

**总体建议：先建立可追溯的“作品组—元素卡—来源/派生文件”索引，再逐步接入 AI 解析；不把“自动抠图”当成全部八类元素。** 遵循总控管理数据/权限，2D 提供图像分析能力，3D 提供可验证的姿势、体型、相机参数。当前 RTX 3060 Ti 8GB，避免一次加载多个大型视觉模型。

### A. 本地索引与保存（优先）
- **SQLite + JSON 元数据 + 文件系统**：SQLite 管作品、元素卡、来源、跨卡引用、版本、审核状态；FTS5 可做文字标签全文检索（中文分词/检索质量需单独评估）。二进制原图、蒙版、预览不塞数据库；放 D 盘分层目录。
- 记录原文件路径与 SHA-256、尺寸、色彩/透明通道、来源/授权、原图只读；同内容文件去重，派生文件另存。路径迁移/丢失需有修复机制。
- 预览用 WebP（必要时无损、带 alpha），原图不自动降采样；蒙版可用单通道 PNG/WebP 或 RLE/多边形，依数据类型选择；缩略图按需缓存并可清理。透明薄纱应保留半透明 alpha，不能仅用二值蒙版代替。
- 元素卡引用原图/裁切范围/蒙版/描述/候选参数/人工确认状态；“原图可见、模型估计、AI 补全、用户确认”分别标记。相同衣装多视角共享一张 O 卡；镜头 K 每个不同机位独立卡；G 含场景专属构图。

### B. 图片理解与元素提取（按难度分层）
1. **轻量规则/图像算法**：读取元数据、生成缩略图、感知哈希候选去重、颜色统计/调色板；这些便宜且可先上线。
2. **视觉语义解析**：可选视觉语言模型（VLM）输出八类候选标签、部件描述和来源证据；采用严格 JSON Schema 校验、可编辑字段、置信度/不确定性。模型能“描述”不代表能准确分割/恢复 3D。
3. **实例/部件分割**：SAM 2.1 的 tiny/small 作为候选，配合点选/框选或外部检测提示，产生可修订蒙版；其强项是分割，并不天然知道“这块是薄纱袖/衣装 O001”。薄纱边缘、发丝、透明叠层需额外 alpha matting 或人工修正，且要测试动漫素材表现。参考：https://github.com/facebookresearch/sam2 。
4. **姿势/脸部特征**：MediaPipe Pose/Face Landmarker 或其他关键点检测器作为候选，输出 2D 关键点与可见性；动漫画风、夸张比例、遮挡会导致失败，不能自动当准确 3D Rig。身材 B 的尺寸/比例同理保留估计标记。
5. **相似检索/合并建议**：感知哈希检测近重复，CLIP/SigLIP/DINOv2 等视觉向量用于候选相似图召回；“同一人物/衣装/场景”需二次确认，不可仅凭向量相似自动合并。DINOv2 官方：https://github.com/facebookresearch/dinov2 。
6. **场景 G / 镜头 K / 画风 S**：场景布局、主体预留区、引导线可用检测/分割+视觉模型描述；K 从单图只能存取景与粗略透视估计，不能凭空获得真实焦距；S 以多图参考、色板、线条/光影/材质描述为主，避免假精确参数。
7. **衣装 O 的模特预览**：第一阶段使用原图参考 + 标准成年女性模特的**示意性二维预览**；把“真正穿着贴合的 3D 试衣”留待未来专门验证，不能把自动分割图贴到 3D 就称为真实试穿。

### C. 模块与性能
- 总控提供本地元素 API、SQLite 索引、后台任务状态和审查/权限边界；2D 分析模块通过受控接口回传结构化结果，不直接写全局数据库；3D 只处理已确认的姿势/体型/相机等结构数据。
- 已有 ComfyUI 服务器提供 HTTP/WebSocket 路由（如 /prompt、/ws），可在未来需要图像后处理时复用，不应为“元素索引”强制启动 ComfyUI。官方：https://github.com/Comfy-Org/docs/blob/main/development/comfyui-server/comms_routes.mdx 。
- 3060 Ti 8GB 下按**先 CPU 轻量索引 → 单任务 VLM/分割 → 结果缓存**的队列执行；模型选 tiny/small、按需加载与卸载；先在实际 Windows 上测显存、速度、质量。SAM 官方速度数字来自其他 GPU，不能照搬。
- 不在 GitHub 上传私人原图、第三方模型权重、敏感参考或大型缓存；本地 D 盘为主。第三方软件、模型权重、训练数据与素材的许可分别核对。

### D. 最小验证实验（以后做，不改变当前开发排期）
- 选 6–10 张用户授权的多样参考：单人立绘、复杂半透明衣装、多视角同款、人物遮挡背景、不同机位、画风差异。
- 验收① 原图无损/可追溯；② 八类卡片可人工建立/编辑；③ 同款多图合并但不同镜头分卡；④ 半透明蒙版质量可用；⑤ 检索、删除缓存、迁移路径可靠；⑥ 自动解析的错误可一键纠正；⑦ 统计实际磁盘占用和 RTX 3060 Ti 显存。
- **优先级**：索引与资源卡 > 半自动解析/人工校正 > 局部蒙版/部件复用 > 自动合并与复杂 3D 预览。所有路线均为候选，实测后可替换，不构成安装授权。


## AI 绘画参考素材库与审美精选库｜2026-11-10（讨论记录）

> **状态：策略备忘，尚未执行批量下载、筛选、训练或实机验证。** 本节讨论供软件使用的 AI 参考/训练素材，与前文八类「作品元素卡」是不同维度：一张图片可以既属于参考素材，又提供某些元素卡，但二者不等同。

### 核心判断
- **技术有用的素材不一定是用户喜欢的成品**：普通摄影、人体结构、姿势、服装纹理、灯光、动漫立绘等，可以分别用于结构理解、参考控制、材质观察和效果验证。
- **决定最终审美的精选图片必须更贴近目标风格**：用户偏好华丽、强立体感、精致皮肤与布料光影、具有摄影质感的动漫/半写实壁纸；不要把任意高分辨率图片自动当作优质风格训练数据。
- **参考不等于训练**：素材在硬盘里不会自动让基础模型学会。应区分按需检索/图像参考、局部参考控制、LoRA 微调、基础模型已有能力。优先用基础模型+精选参考验证，反复不足时才考虑训练 LoRA；不承诺杂糅素材能自动学出目标风格。

### 推荐两层逻辑分类（允许同文件多标签，不重复复制）
1. **通用技术参考库**：人体/姿势、布料/服装结构、光照/摄影、一般动漫插画、材质等；按用途、质量、来源、许可、格式、分辨率标记。
2. **审美精选库**：用户明确认可的风格/角色/皮肤/材质/光影示例，作为风格目标和视觉验收标准；比数量更重视一致性与高质量。
- 两层属于**逻辑标签/视图**，不必新建 GitHub 仓库，也不必复制原始图片；继续使用总控统一索引、D 盘原档及派生缓存。
- 单张图可同时标记「技术参考：光影」和「审美精选：否」，或同时属于两者。

### 下载与筛选
- 用户准备**边下载边研究**，无需先下载整个大型加密分卷压缩包。可按批次读取可访问的文件/抽样图，记录实际尺寸、文件格式、是否透明、锐度、压缩痕迹、重复/近重复、画面遮挡文字、结构质量、审美匹配与许可。
- 4K 不必一律保留：2K 通常足够常规参考，4K 对局部裁切、细纹理和高清存档更有价值；**原生细节比简单放大像素更重要**。保留原档，只对精选参考生成轻量预览；是否删除原档需用户明确确认。
- 带文字框/录制边框的插画仍可能有参考价值，但用于训练前应评估干扰、去重和清理；相似多图可能帮助角色多视角参考，但在训练集中不能无节制重复。
- 样本仅能代表样本，不据少数图片断言整套资源的平均画质；缺失分卷或密码验证失败时如实标记未检查。

### 训练与能力边界
- 首先复用已有 checkpoint 的通用绘画能力；按需提供姿势/3D 相机、参考图、局部蒙版等控制，不把每种素材都转成训练集。
- 风格 LoRA 需要审美一致、版权/使用许可可接受的精选数据和实测；8GB 显存下训练配置、时间与效果需单独评估。不要把非目标画风的大量图直接混入风格训练集。
- 素材是否允许私人参考、训练、再分发是不同许可问题；第三方购买资源不默认允许公开或训练，记录来源和权限。
- 这属于**素材策略与后续验证任务**，不改变当前 2D 实机出图、总控入口、3D 姿势/相机闭环的开发优先级。
