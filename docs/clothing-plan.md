# 衣装搭配思路

状态：设计思路，尚未实现或在实际模型上验证。更新：2026-11-11。

## 目标

衣装是 3D 模块中的一个小功能：三种固定基础身材、固定姿势、简单搭配，以款式和大轮廓正确为目标。衣服保存为三维成衣；精细纹样、蕾丝和最终画面修整交给 2D。本阶段不做动画、实时布料、任意体型适配或 MD 裁片编辑。其他文档中的长期体型、动画规划不作为本功能的前置要求。

## 自建什么，复用什么

采用“自建使用界面与连接代码，复用成熟处理工具”的方式。

| 部分 | 做法 |
| --- | --- |
| 画室界面 | 自己搭建：衣服卡片、部件开关、搭配收藏、恢复上一套 |
| 资产管理 | 自己搭建：服装 ID、适配记录、来源、缩略图与搭配存档 |
| 三维处理 | 复用 Blender 的模型、变形、基础材质和导出能力；必要时写自动化脚本 |
| 服装贴合 | 优先验证 Blender 自带工具；现成插件作为可替换的候选，不绑定某个插件 |
| 二维生成与精修 | 沿用项目 ComfyUI 方向；按需要接入局部重绘，参考 Krita 的蒙版与恢复流程 |
| 模型与素材 | 使用已有、允许使用的资产；不从零开发生图模型或完整三维编辑器 |

Blender 和 ComfyUI 是后台软件，插件是补充功能，画室自己写的代码负责把它们连接起来。用户最终通过一个简单入口操作。外部工具接入仍需要安装配置、格式转换、错误处理和效果验证，不能把“有插件”当成已经实现。

## 用户流程

选身材 → 选固定姿势 → 点选衣服与配件 → 旋转查看 → 保存搭配／送往 2D。

默认同部位替换，明确允许叠穿的组合再开放。项链、帽子、腰饰等有搭配价值的配件独立开关；不把每个小零件都拆成操作项。界面只展示已验证的适配组合，不要求用户刷权重或反复拖动微调滑条。

## 后台处理

1. 导入成衣，保留原件，记录来源与适用身材。
2. 先做位置、比例对齐，再进行必要的局部修形与变形绑定。优先统一三种身材的骨架和参考姿势，但需检查实际资产是否满足。
3. 将衣服适配到目标固定姿势，检查明显穿模和轮廓问题。骨架可用于摆姿势，不要求制作动画。
4. 保存处理后的静态结果，按实际使用缓存身材／姿势组合，不预先生成所有排列。
5. 宽松裙摆、贴身衣物和刚性饰品分别处理。表面变形不等于布料碰撞求解，不能把裙摆全部吸附到腿上。

新衣服第一次入库可能需要修正；已经适配好的衣服供后续直接选择。三种身材和固定姿势降低的是反复计算及兼容范围，不代表任意衣服都能零调整导入。

## 如何保存

- **源工程**：保留可编辑 Blender 文件、基础材质与必要绑定，方便再次修正。
- **画室资产**：导出处理后的静态 GLB，画室直接加载，不要求它运行 Blender 修改器。
- **搭配记录**：保存衣服／配件 ID、身材、姿势、颜色和显隐状态，避免每套都重复复制人体。
- **预览与索引**：缩略图、适配状态、版本及来源。实际模型和纹理放本地素材目录，GitHub 保存程序与说明。

薄纱需要保留内层身体与基本透明关系；只对不透明遮挡区考虑可逆隐藏身体。不同软件的材质不保证原样转换，需以画室实际显示结果验收。

## 2D 衔接

先保留原始三维渲染图，后续局部重绘结果另存。拟增加衣服区域蒙版，让系统知道哪里允许修改；面部、头发和遮住衣服的手臂应尽量保护。支持前后对比与恢复，细节修正不要求用户学习专业面板。透明布料与皮肤混合的区域需单独检查，不承诺自动分离准确。

这些是后续接口建议，不表示当前已实现蒙版重绘，也不改写现有 3D 导出协议；实施时再统一更新协议。

## 第一版验收

先用一件上衣打通导入、适配、保存、重新打开，再扩展至三种身材和少数固定姿势。确认款式可辨、无明显穿模、旋转无明显空洞、配件开关正常、搭配可以恢复后，再加更多衣服。详细材质与局部精修留给 2D。
