# 模块职责｜三个仓库

总控管理一套软件，2D 和 3D 独立执行专业任务。产品体验以[产品体验](product-ux.md)为准，完成状态集中在[开发状态](roadmap.md)。

| 能力 | 总控 | 2D | 3D |
| --- | --- | --- | --- |
| 统一入口、房间导航、配置与任务 | 负责 | 提供模块接口 | 提供模块接口 |
| 绘图模型、LoRA、采样、重绘 | 调用与展示 | 负责 | — |
| 人体、骨架、姿势、形变、成衣适配 | 选择与展示 | — | 负责 |
| 相机与 RGB/Depth/Normal/Pose | 调度、验证交接 | 转换为生成控制输入 | 生成；维护导出协议 |
| 素材、来源、权限、标签与版本 | 统一索引与策略 | 按授权读取引用 | 按授权读取引用 |
| 作品、人物配方与历史 | 负责 | 返回任务和结果 | 返回资产、姿势、相机信息 |
| 后续动画 | 入口、配方和编排展示 | 分层与图像微动画 | 骨架、次级运动与导出 |

## 过渡与工具复用

保留 2D 现有安装脚本、启动器、服务和网页；总控连接并通过验证前，不搬空或删除真实代码。过渡期间存在开发入口不代表两个正式软件。

模块通过本地 API 或已验证文件包通信，不直接导入彼此私有函数或全局状态。接口细节见[协作接口](integration.md)。

画室自建统一界面、资源索引和连接逻辑；三维优先复用 Blender 和授权模型，二维复用 ComfyUI。插件是可替换候选，不是“装上即实现”的承诺。

## 模型与资产

先选用并适配一份可验证的连续成年女性人体母版，不把从零原创建模作为前置条件；原有 body 人脸研究不算完整人体。3D 可独立欣赏，也为 2D 提供结构参考。体型与姿势产品规则见[元素与素材](element-library.md)，近期成衣限制见[衣装方案](clothing-plan.md)。

作品、动画、衣装和素材均先作为现有仓库内模块，不额外扩仓库。代码与公开说明放 GitHub；大资产、私人原件和模型权重留本地。访问和共享规则集中在[AI 协作](ai-collaboration.md)。
