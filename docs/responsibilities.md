# 三仓库职责与边界

**判断是否应放进本仓库：** 与“一个软件如何连接和管理多个模块”有关的代码/规范放总控；与具体生图或建模算法有关的工作留给专业模块。

| 能力 | 总控（本仓库） | 2D 模块 | 3D 模块 |
|---|---|---|---|
| 用户启动、统一导航、统一配置 | **负责** | 暂保留历史开发启动器 | 只提供模块入口 |
| 作画模型、LoRA、采样、重绘 | 调用、显示状态 | **负责** | 无 |
| 成年人体基模、Rig、形态修正 | 调用、显示状态 | 无 | **负责** |
| 姿势、相机、Depth/Normal 导出 | 选择、传参和校验返回 | 消费控制包 | **负责生成** |
| 3D → 2D 数据协议 | 调度，版本兼容提示 | 适配 ControlNet | 拥有原始导出规范 |
| 素材、来源与权限、标签索引 | **负责统一目录和访问策略** | 根据授权取引用 | 根据授权取引用 |
| 图像历史、作品、人物配方 | **负责** | 返回任务和生成结果 | 返回模型、姿势和相机 ID |
| 内容审查和用户授权 | 统一审批/隔离规则 | 执行工具适用限制 | 执行工具适用限制 |

## 现有代码的过渡安排

目前 2D 仓库仍有安装脚本、`launcher.py`、`app/server.py` 和 `app/web/index.html`：**先保留这些真实文件和可运行路径，不强行复制或删除。**

新总控仓库暂时只负责整体计划和接口；等 2D 在 Windows 上确实能运行、总控启动器得到本地验证后，逐项迁移软件统一 UI 和启动功能。成功之前两个入口的存在属于**开发过渡**，不对用户推出两个正式软件。

新总控不直接导入 2D 内部 `workflows.py` 或 Blender 的私有全局状态；通过受控本地 API / 已验证的文件交接。这样单独更新 2D 或 3D 不会无意破坏另一个。

## 成年人体母版

3D 中先做**一个原创成年女性参数化基模**，而不是为每种 2D 画风分别建模；先验证骨骼、站立/侧身/坐姿/举手/跪姿和多角度。以后加入体型滑条、服装、角色一致性与动态。

审美意义上的“理想比例”是用户可选预设，不应宣称所有成年女性只有一种标准体型。ZBrush/解剖教材可作为雕刻技术参考，不把 PDF 知识等同于完成的 3D 资产。

## 存储与私有素材

统一索引记录：文件 ID、原路径、派生路径、来源/作者、访问层级、使用目的、许可状态、成年判断依据/不确定项。保留原图，衍生图尽可能可追溯。

- 用户的私人素材目录与可供 AI 调用的精选参考目录隔离。
- 敏感参考原件和大文件不提交公开 GitHub。
- AI 代理只通过经过约束的模块调用获得授权输入，不能因 UI 隐藏按钮就认为权限隔离完成。
- 严格区分角色官方年龄、剧情可支持的成年推定、年龄未知。未成年人不得进入成人参考处理池。
