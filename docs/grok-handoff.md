# Grok 协作评审说明｜总控/2D/3D 三库方案

用户准备把「幻真画室」拆成三个技术仓库，但使用时仍希望是一套软件。请以**独立模块、统一协议、保留现有代码**为前提评审。

## 当前事实

- 总控：本仓库 `Fantasy-Studio-`，刚建立总体文档；没有可运行的统一启动器。
- 2D：`Fantasy-Studio-2D` 已有 Python + HTML 和 ComfyUI 桥接，文生图、img2img、LoRA 功能已编写但未在用户 RTX 3060 Ti 上完成真实 GPU 验收。
- 3D：`Fantasy-Studio-3D` 有模型/姿势/EXR/关键点的规范与脚本雏形，**暂无完成的全身人体基模或可用导出**。
- `body` 为独立人脸研究，不要误当成已完成的全身模型。
- GitHub 2D/3D 公开，总控仓库目前为 private；原始私人/敏感资料不能提交公开代码库。

## 请重点审查

1. 是否同意**总控负责统一 UI/启动/任务与历史，2D 负责生成算法，3D 负责 Rig 和结构导出**？
2. 现有 2D 仓库有启动器与网页 UI：如何循序迁移到总控而不破坏功能？是否可以先“总控打开 2D 现有服务”，再逐渐抽取共用 UI？
3. 3D 用文件包（manifest+RGB/Depth/Normal/Pose）和 2D 交换是否合适？有没有更少耦合的设计？
4. Windows 上如何处理 2D（ComfyUI）与 Blender 资源占用，避免显存冲突？
5. 统一私人资料访问控制应放在哪里？怎样确保 AI 默认不访问仅用户手动管理的资料？
6. 后续需要真人体型母版、换装和角色一致性时，哪些数据归属于 3D 模块，哪些归属于总体角色档案？

## 期望反馈

请提供具体可执行的修改意见、最高风险和建议实现顺序。不要把静态 HTML、协议草案说成实际运行功能。先评审，不要自动安装大模型或批量迁移、删除任何旧文件。
