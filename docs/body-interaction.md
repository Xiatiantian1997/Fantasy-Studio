# 身体互动｜可行性与资源初查

更新：2026-11-11。当前为方案与资料核查，未实现、未做 Blender/浏览器运行验收。百度云资源尚待补充，本页不是全部素材的盘点。交互入口以[产品体验](product-ux.md)为准；实验校准见[软组织实验](soft-tissue-test.md)。

## 初步判断

轻量次级运动和有限区域的按压回弹可以作为独立实验推进。资源数量不是主要瓶颈；模型是否有合适骨架、权重、形态键，以及衣服能否跟随同一套形变，决定适配工作量。成熟工具可减少求解器开发，不能替代资产适配。

这里的“柔软”分两层：皮肤光泽、粗糙度、纹理属于材质外观；受力形变、惯性与回弹属于几何运动，两者不能用一个滑条相互替代。

| 能力 | 初步难度 | 可采用的方法与限制 |
| --- | --- | --- |
| 皮肤外观预设 | 中 | 调整材质与灯光；浏览器与 Blender 的着色效果需分别校准 |
| 轻微胸部、发丝等次级运动 | 中，前提是已绑定模型 | 弹性骨骼及阻尼；适合近似晃动，不等于完整软组织体积模拟 |
| 简单点按反馈 | 低至中 | 射线选区加预设反馈；点击检测本身不会使网格变软 |
| 有限区域按压与松开回弹 | 中至高 | 预制形态键或局部变形加回弹；限制位移和区域，防止自交与体积塌缩 |
| 任意部位接触、局部挤压 | 高 | 需要锚定、体积约束、自碰撞、不同姿势修正；暂不承诺 |
| 服装随身体一起变形 | 高 | 匹配骨架、蒙皮和修正形态；静态成衣不能自动支持动态 |
| 同一瞬间拍照与结构图 | 中至高 | 固定同一份几何、骨架、相机和模拟状态，再生成各输出通道 |
| 三身材、多姿势、不同衣服通用 | 高 | 组合验证与适配工作量增加；先收敛到一身材、一衣件 |

难度是工程判断，不是已经测得的工时或成功率。普通触屏拖动只能提供位置/位移输入，不应假定设备能测出真实按压力度。

当前优先目标收敛为精选动作之间平滑过渡，加适度次级晃动。按压交互仍是可选实验，不阻塞动作展示；开源选择与最小验收见[动作与晃动](motion-reuse.md)。

## 推荐技术分工

- **Blender：资产准备与离线烘焙。** 骨架、权重、修正形态、碰撞代理在此制作。Wiggle 2 可研究弹性骨骼、碰撞和烘焙流程；需核对插件与 Blender 版本及许可。
- **网页预览器：实时观察与输入。** Three.js 的蒙皮模型需要骨架、蒙皮索引和权重；Raycaster 用于命中检测。VRM 路线可评估 three-vrm 与 springBone。普通 GLB 加载不等于自动启用 VRM 物理。
- **实时交互与烘焙动画分开验收。** glTF 可携带骨骼/形态键动画，但不能假定 Blender 内部求解器、驱动器和约束随模型原样运行。固定循环可以烘焙；用户临时按压需要运行时响应。
- **全体积软体暂缓。** 先用弹性骨骼处理整体次级运动、有限形态键处理局部按压；必要时再研究更复杂求解器。二者叠加的顺序和范围仍需测试。

## 已检查的有限样本

对用户已提供的三份 FBX 和一份 GLB 做了只读文件结构解析，未渲染、未做姿势或变形测试；不在公开仓库记录私人文件名、下载链接或文件内容。

| 样本 | 结构发现 | 当前可推断的用途 |
| --- | --- | --- |
| FBX A | 197 个网格，约 77.9 万顶点条目；未检出蒙皮 Deformer；有动画容器但无动画曲线 | 静态/结构参考候选，尚非可直接驱动人体 |
| FBX B | 194 个网格，约 78.7 万顶点条目；未检出蒙皮 Deformer；有动画容器但无动画曲线 | 同上；不能因存在动画容器就认定有可播放动作 |
| FBX C | 54 个网格和 1 个 Shape；约 122 万顶点条目含 Shape 数据；1 组形态键相关结构，未检出 Skin/Cluster/LimbNode | 解剖或形态参考候选；一个形态键不足以证明全身可调或可触摸 |
| GLB D | 1 个网格，约 2.1 万顶点；无 skins、animations、morph targets | 静态姿势预览/结构参考 |

条目数不是去重后的表面顶点数；多网格与较大几何量提示需要检查绘制次数、纹理和简化方案，不直接证明无法运行。以上结论不覆盖百度云中的其他模型。

## 仍然困难的部分

1. **好看的模型不一定能动。** 缺少合适拓扑、权重或修正形态时，需要重新绑定或另选母版；解剖分件也不会自动形成相连的软组织。
2. **动态与衣装范围冲突。** 近期衣装是固定三身材、固定姿势。身体动态实验单独开启；未适配衣件应锁定相关形变或回退静态，并明确提示能力限制。
3. **透明衣料与选区。** 半透明排序、薄层遮挡和命中规则需要单独处理，射线命中三角形不等于用户眼中实际可见的布料区域。
4. **移动端手势与状态恢复。** 区分旋转和按压；处理手指移出、系统取消输入、退出互动，防止模型保持变形或误隐藏衣物。
5. **预览和导出一致。** 拍照时冻结求解器、骨架及形态值；跨浏览器/Blender 重现需要验证，不能只传几个滑条值就承诺同帧一致。
6. **性能与显存竞争。** RTX 3060 Ti 8GB 上实时预览与生成同时运行的成本待测；必要时生成时暂停动态、降低预览质量。尚无帧率承诺。
7. **2D 成图一致性。** 3D 提供姿势和遮挡参考，不保证生成图保留全部身份、衣服细节或透明度。图像转模型的背面与隐藏结构也仍是推测。

## 最小验证顺序

1. 选择一份来源明确、带可用骨架和权重的成年人体；确认材质、形态键和导出。
2. 一种身材、少量固定姿势，加入一组轻量次级运动；测停止后稳定、切换姿势不爆振。
3. 一个有限按压区域，验证选择、按压、释放、取消输入和复位；先以非敏感区域校准通用算法。
4. 加入一件兼容衣服，观察遮挡与穿模；不支持动态的衣服保持静态模式。
5. 冻结一帧，检查 RGB/Depth/Normal/Pose 是否来自一致状态；导出后重新打开验证。
6. 记录实际帧率、显存、模型大小和失败情况，再决定是否扩展三身材、多衣服及更多互动区域。

界面不要求用户刷权重或调求解器。基础提供少量预设和三个主要控制：柔软度、回弹速度、晃动幅度。高级刚度/阻尼仅按需展开；其映射不是简单同义替换，需要标定。

## 百度云资料后续怎么筛

截图先用于判断候选，不据文件名认定能力。优先看文件名/后缀、预览、软件和插件版本、文件说明：

- **可直接试用候选**：带骨架与蒙皮的 .blend/.fbx/.vrm/.glb，说明含形态键、可换装或配套骨架；仍需实际打开。
- **需要适配候选**：有模型但骨架不同、衣服没有权重、材质依赖特定插件，或仅含高模。
- **参考资料**：立绘、预览图、解剖展示、视频教程；可帮助审美和制作，不替代运行资产。

优先补齐“一份可驱动母版 + 一件兼容衣服 + 对应版本教程”，再决定需要哪些额外资源，不要求先搬运整个网盘。

## 主要技术来源

- [VRMC_springBone 1.0](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_springBone-1.0/README.md)：惯性、阻尼、刚度与碰撞约束。
- [VRM Spring Bone](https://vrm.dev/en/univrm/springbone/univrm_secondary/)：次级骨骼运动用途。
- [three-vrm](https://github.com/pixiv/three-vrm)：VRM 加载与运行时集成候选。
- [Three.js SkinnedMesh](https://threejs.org/docs/pages/SkinnedMesh.html) 与 [Raycaster](https://threejs.org/docs/pages/Raycaster)：蒙皮及选区基础。
- [glTF Blender 导出器说明](https://github.com/KhronosGroup/glTF-Blender-IO/blob/main/docs/blender_docs/scene_gltf2.rst)：动画与导出限制。
- [Wiggle 2 原作者仓库](https://github.com/shteeve3d/blender-wiggle-2)：碰撞、弹性骨骼与烘焙。
