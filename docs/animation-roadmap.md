# 幻真画室｜程序化动画系统开发方向

> 2026-11-11 · 规划稿。技术路线与验收标准，不代表功能已实现。公开仓库仅存通用动画技术和合法演示素材；私人素材由用户本地独立管理。

## 当前优先目标

用户明确以“喜欢的动作平滑过渡，并带适度柔软晃动”为目标。先做少量精选动作和轻量弹性骨骼，不以全套动作积木、连续体型、Spine 验证或视频动捕为前置。床和泳池相关大动作后续再扩展。开源候选、FlowHMR 借鉴记录与最小验收集中见[动作与晃动](motion-reuse.md)。下文阶段 A–F 保留为长期扩展路线，不作为近期全部必做项。

## 一、最终目的

让用户选择人物、体型、基础姿势和若干动作积木，调整顺序、时长、速度、幅度及镜头，即可获得自然连贯、可旋转预览的 3D 动画，并将其作为 2D 微动画、姿势参考和渲染输出的基础。用户不需要直接操作关键帧、骨骼曲线或节点。目标是**少量高质量动作样本 + 可复用的数学规则 + 自动过渡/约束**，而不是积累大量无法组合的固定 GIF。

3D 动画是独立展示能力，不应沦为 2D 生成的附属品；2D 成图也不应被迫先启动 3D。动画是可选模块，优先保证现有 2D 出图和 3D 模型/姿势/相机闭环。

## 二、架构分层

```text
用户界面：角色 / 体型 / 姿势 / 动作积木 / 时序 / 镜头
                         |
动作编排器：事件、顺序、重叠、混合权重、循环与过渡
                         |
主运动层：骨架、FK/IK、根运动、姿势插值、接触点锁定
                         |
次级运动层：弹簧/阻尼、惯性、局部骨骼、形态键、网格权重
                         |
约束修正层：关节极限、地面接触、自碰撞、体积与穿模检查
                         |
角色适配层：骨架映射、体型参数、局部权重、挂点与坐标系
                         |
预览/导出：3D 实时预览、Blender 烘焙、MP4、GIF、结构控制图
                         |
2D 可选后处理：分层、网格绑定、遮挡补画、轻量形变
```

### 2.1 基础姿势
少量精选站立、坐姿、跪姿、俯身支撑、躺卧等姿势预设；记录支撑点、骨架版本、姿势适用范围。姿势不与体型、相机绑定。

### 2.2 主动作积木
动作积木表达**独立的运动意图**，例如转头、抬手、重心转移、俯身、站起、摆动、行走。每个积木声明受控骨骼、时间曲线、开始/结束姿势、循环性、支撑约束及可中断点。不要按“动了几个身体部位”计数动作。

### 2.3 次级响应通道
同一主运动可驱动多个独立局部响应：头发、衣物、胸廓、软组织、配饰。它们共享运动事件，但各自有幅度、延迟、频率、阻尼、权重与约束。两个部位一起晃动通常是一个主动作加两个响应通道；若有两个独立主动驱动，则是两个可编排动作。

推荐最小数学模型（示意，不宣称生理真实性）：

```text
m * x'' + c * x' + k * x = F(t)
```

其中 F(t) 来自主骨骼的加速度或外部作用；不同局部使用不同的 m、c、k 和网格权重。可用固定时间步长的稳定数值积分或经验证的解析近似。与单纯正弦循环相比，这样能让动作加速、停止、反向时产生相应的延迟回弹。

### 2.4 时间编排与混合
支持串行、并行、交叠、淡入淡出、循环、事件触发；骨骼层与局部响应层分别混合。姿势插值采用合适的四元数旋转和约束处理，不能简单对所有欧拉角求平均。相邻动作的速度、加速度应尽量连续；用户可一键调整节奏。

### 2.5 体型连续适配
提供纤细/标准/丰满等快捷预设，底层使用连续参数。位移可按身体尺度归一化，但回弹频率、阻尼和连接约束不能只按体积机械缩放。每个角色/区域保留独立权重、形态键与安全范围；避免为每个体型手工重做全部动作。

### 2.6 约束与质量
重点解决：手脚支撑点滑移、关节超限、穿模、局部网格撕裂、体积异常、动作切换时跳变、配饰漂移。接触点可使用 IK 锁定，局部变形需检查网格权重与相邻区域连续性。大跨度姿势切换不能保证自动合理，应提供中间姿势或报告无法平滑过渡。

## 三、现有素材的研究与提取

- **Spine 原始工程**：先识别数据版本、骨架、mesh、deform、IK/transform/path constraints、曲线、draw order 和贴图。优先用授权合规且版本匹配的 runtime 播放；简化渲染器只能作降级预览，不能把缺失约束的结果当作原版动画。
- **MP4/GIF**：可观察动作节奏和画面效果，但必须先区分镜头运动、身体主运动与局部相对位移。不能从单段视频唯一反推出骨骼、材质刚度或真实质量。
- **FBX/BVH/GLB/Blend**：检查骨架映射、单位、坐标轴、帧率、root motion、骨骼命名、蒙皮、许可与动作兼容性。保留原始文件只读。
- **规则提取**：记录运动周期、相位、峰值、延迟、衰减、速度曲线和置信度；拟合多个候选模型并与原动画对照，不把经验拟合说成真实物理参数。
- **素材库**：每个样本记录来源、授权、角色 ID、骨架版本、动作名称、时长、可循环性、适用姿势、质量、渲染器版本和已知缺陷。用户认可的精选预设与未经验证的原始样本分开。

## 四、3D 与 2D 的关系

**3D 主线**：优先复用 Blender、已有连续人体网格和骨骼；研究 Three.js 或合适的实时查看器用于自由旋转、缩放、播放与参数调节。Blender 用于复杂绑定、形态键、烘焙和离线输出。不得承诺所有模型直接零成本适配。

**2D 支线**：对可分层插画使用网格、局部骨骼、补画遮挡和形变规则实现眨眼、呼吸、发丝/配饰摆动等微动画。静态 PNG 不自带隐藏图层与骨架，自动分层失败时应明确提示、允许手动修正或回退静帧。3D 姿势可提供 2D 关节投影，但不能自动还原图片内部的像素结构。

**导出**：优先保证流畅 MP4（目标 30 FPS 起，必要时 60 FPS）；GIF 仅作便捷预览。输出还包括姿势、相机、RGB、Depth、Normal、Pose 等现有 3D→2D 接口需要的结构信息。

## 五、交互设计

首页只暴露：人物、体型、姿势、动作、时长/速度/幅度、镜头、播放/暂停、保存/导出。高级设置中可编辑局部响应通道、骨架映射、约束和动画曲线。手机或平板预览使用大按钮与触控旋转；不要求用户直接编辑代码。

典型流程：
1. 选一个已绑定的成年角色及体型。
2. 选基础姿势与两个动作积木。
3. 指定先后顺序和短暂重叠；系统生成过渡。
4. 启用头发、衣装等次级响应并调整幅度。
5. 在可旋转 3D 视图中检查脚滑、穿模和不自然回弹。
6. 保存为动作配方，导出 MP4 或送往 2D 控制流程。

## 六、建议的数据接口

建议独立版本化 `animation_recipe.json`，与角色资产和私人素材分离：

```json
{
  "schema_version": "0.1",
  "character_id": "adult_base_01",
  "rig_profile": "humanoid_v1",
  "body_preset": "standard",
  "base_pose": "kneeling",
  "timeline": [
    {"action": "look_left", "start": 0.0, "duration": 1.2, "weight": 1.0},
    {"action": "raise_hand", "start": 0.8, "duration": 1.5, "weight": 1.0}
  ],
  "secondary_motion": {
    "hair": {"enabled": true, "gain": 0.5, "damping": 0.7},
    "accessory": {"enabled": true, "gain": 0.3, "damping": 0.8}
  },
  "output": {"fps": 30, "duration": 3.0, "format": "mp4"}
}
```

这是**建议接口，不是已经运行的 schema**。未来需要与 3D 仓库 `docs/interface-v0.1.md` 对齐，避免出现两份互相矛盾的模型/相机/坐标定义。

## 七、分阶段实施与验收

**阶段 A｜可靠播放**
- 选 1 个已授权的完整 3D 人体模型和 1 份 Spine 样本。
- 验证骨架、网格、约束、相机与动画时间曲线；输出连续流畅的预览。
- 验收：没有明显破面、贴图错位和不合理跳帧；保留失败记录。此前 5–16 帧的实验 GIF 不算通过。

**阶段 B｜最小动作积木**
- 两个基础姿势、三个主动作积木、一套插值与时间编排器。
- 验收：动作可顺序/重叠组合，播放速度可调，关键支撑点不明显滑动。

**阶段 C｜次级运动与体型**
- 至少两种独立响应通道；三个体型预设加连续微调。
- 验收：相同动作配方可跨体型运行；动作停止后局部响应合理衰减，不明显穿模。

**阶段 D｜3D 产品化**
- 自由相机、预设管理、动作库检索、实时预览、MP4 导出、失败回退。
- 验收：用户无需接触 Blender 时间轴即可完成一次动作组合和导出。

**阶段 E｜2D 微动画**
- 选择一张有足够分层信息的插画，完成一至两种局部循环动作。
- 验收：遮挡补画正确、画面没有明显撕裂，能导出可观看 MP4/GIF。

**阶段 F｜样本规则提取**
- 批量分析已授权的 Spine/3D 动画，记录运动曲线、拟合误差和适用范围。
- 验收：提取的规则能在不同角色或不同速度下复用，且效果优于简单固定帧复制。

## 八、实施原则与当前边界

1. 先修复**原动画准确播放**，再追求大量导出和自动规律学习。
2. 不重复造 Blender 或 Spine 的全部能力，优先接入成熟工具与合规 runtime。
3. 规则可复用不代表所有人物、骨架和体型零适配成本。
4. 先完成一个可验收的小闭环，再扩展素材数量与动作类别。
5. 2D 与 3D 共享动作语义和参数约定，但不假设共享同一套网格/骨架。
6. 公开仓库不保存私人素材、付费游戏贴图或未经许可的角色资源。
7. 本文是长期方向；不覆盖现有“先验证 2D 出图、再建立 3D 姿势相机闭环”的总体实施顺序。
