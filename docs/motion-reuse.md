# 动作与晃动｜开源借鉴

更新：2026-11-11。资料和部分源码核查；未安装、移植或实机验证。记录用户当前最高目标：**少量喜欢的动作可以平滑过渡，并带适度柔软晃动、延迟与回弹**。不以完整软体模拟、自动动捕或任意动作自动衔接作为前置条件。

## 推荐组合

1. 主运动：同一已适配骨架上的精选动作，使用动画混合、根位置/朝向对齐与必要过渡片段。
2. 支撑约束：在指定时段锁定脚或手的支撑点（IK，即根据接触点反算关节），避免滑动。
3. 次级运动：主运动后叠加弹性骨骼与阻尼，驱动头发、配饰和已绑定柔软区域；需要局部形状修正时补形态键。
4. 展示：先完成一套可重复播放的烘焙结果；需要实时调参时再加入运行时求解。

动作混合只解决权重过渡，不会自动生成合理起身过程。站到坐、坐到躺等跨度较大组合需要中间片段或手工校正；首版只开放经过验证的相邻动作组合。

## 开源候选

| 项目 | 适用部分 | 接入判断 |
| --- | --- | --- |
| [Three.js AnimationAction](https://threejs.org/docs/pages/AnimationAction.html) | 动作交叉淡入淡出、时间缩放、权重混合 | 网页预览候选；需自行做好支撑点、根运动与过渡片段 |
| [three-vrm springbone](https://github.com/pixiv/three-vrm/tree/dev/packages/three-vrm-springbone) | 实时弹性骨骼、惯性、阻尼与碰撞 | 若采用 Three.js/VRM，优先评估；普通 GLB 不会自动获得 VRM 物理配置 |
| [Wiggle 2](https://github.com/shteeve3d/blender-wiggle-2) | Blender 弹性骨骼、碰撞、预滚动、烘焙关键帧 | 先做离线样片的优先候选；锁定并验证插件/Blender 版本 |
| [JigglePhysics](https://github.com/naelstrof/JigglePhysics) | Unity 实时晃动、伸缩、角度约束与碰撞 | 适合研究参数与求解思路；当前不为它单独迁移到 Unity |

three-vrm 源码可见独立 springbone 包，关节更新含刚度、重力、阻尼、碰撞和复位。JigglePhysics 作者明确以易于创作而非物理精确为目标；适合视觉次级运动，不等于组织体积模拟。Wiggle 2 可将可见弹性骨骼烘焙为关键帧，但烘焙后不会继续响应任意新输入。

仓库标注：three-vrm 与 JigglePhysics 为 MIT，Wiggle 2 为 GPL-3.0。后续抽取代码需保留对应许可与署名；本次只记录候选，不复制第三方源码。新版本或维护分支不能仅凭名称判断兼容，必须随实际 Blender 版本验证。

## FlowHMR 借鉴记录

- [FlowHMR-Windows](https://github.com/xiaoerofficial021-collab/FlowHMR-Windows)：后续视频转动作的候选。当前只借鉴选片段、同步预览、历史任务、滤波与导出流程。
- [FlowHMR 上游](https://github.com/flowhmr/flowhmr)：动作重建模型；训练和完整物理跟踪环境暂不引入。
- [RGB MoCap](https://github.com/toyxyz/toyxyz_RGBMocap)：可参考骨骼映射、脚底接触区间、重定向与导出。已抽查 mapping.py、pipeline.py、foot_contacts.py；映射对骨骼名称/层级有要求，不能视为任意模型通用。
- FlowHMR-Windows 的 runtime_motion_filter.py 约 2KB，RGB MoCap 的 mapping.py 约 2.5KB；文件虽小，仍依赖数学函数、数据结构及其他模块，不能独立复制即用。
- FlowHMR 2 MMR v1.3.1 发布压缩包约 46KB：将导出 FBX 转给已由 MMR 生成的目标控制骨架。插件文件小，不代表骨架适配已完成；尚未检查该 ZIP 内源码。
- windows-v0.2.0 基础包约 492MB，另需推理环境和模型；这不是完整安装大小。
- “8GB 可用”不能当作 3060 Ti 验收。[RGB MoCap 性能报告](https://github.com/toyxyz/toyxyz_RGBMocap/blob/main/docs/PERFORMANCE.md)中的 60 帧 FlowHMR 低显存测试约 2.77GiB，来自 RTX 5090/96GB RAM，不能外推长片或其他机器。
- 当前仍暂缓动捕安装，床、泳池和大动作扩展时再评估。已有动作文件可先走重定向与播放，无需运行视频识别网络。

## 最小验证目标

采用一位成年模型、一种身材、一件兼容衣装、三个相近的短动作。用户只需选择动作、过渡时长、速度、晃动强度及回弹预设。

- 验证 A→B、B→C、循环接缝，以及中途停止；主动作不突然跳变，支撑点不明显滑动。
- 先用一组弹性骨骼：动作加减速会产生响应，停下后自然衰减；转动相机不驱动身体晃动。
- 主动作与物理骨骼分层，避免动画每帧覆盖物理，或烘焙晃动和实时晃动重复叠加。
- 连续动作切换保留适当速度状态；瞬移、换模型、时间轴跳转时采用明确复位/预滚动策略。使用受控时间步长，防止卡顿后爆振。
- 肩、胸廓、骨盆等连接处固定合理；碰撞代理加幅度限制，不把骨骼球体碰撞当成完整网格自碰撞。
- 衣服跟随同一套骨架/权重；不能兼容的搭配限制动态，不承诺125套衣服直接支持。
- 输出可旋转预览及短视频，记录实测帧率、显存和失败项；固定一帧时各结构图使用同一状态。

轻量弹性骨骼不需要大模型权重；主要工作量在模型绑定、权重、过渡片段和衣装适配。当前只确认技术路线可评估，不承诺效果已达到用户审美要求。
