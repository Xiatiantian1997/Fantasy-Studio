# 幻真画室｜单一界面设计

**原则：简约而不简单；一个软件、一个用户入口、三个技术仓库。** 本文是体验规划，不代表相关功能已实现。2D 与 3D 独立开发，由总控统一呈现；用户不必操作 ComfyUI 节点图或 Blender 复杂面板。

## 四个主入口

1. **2D 绘画**：人物、幻真动漫 / 半写实插画 / 数字油画、参考图、生成、局部重绘与比较。
2. **3D 姿势与取景**：选择固定成年角色或简化姿势体块，选择/微调姿势，设置真实虚拟相机，生成 2D 所需的结构参考图。
3. **素材库**：统一索引姿势线稿、人物、画风、结构、未来服装/材质参考；保留来源和访问权限。
4. **作品**：保存角色、姿势、取景参数、提示词/配方、结果、历史与修改记录。

## 核心体验：先摆姿势，再取景，再出图

**姿势选择**：从姿势图库/线稿选择接近的动作；优先用已有带骨骼人体在 Blender 中匹配，或在早期用简化 3D 体块快速预览。同一用户界面里可调整身体整体朝向与必要关节。线稿是姿势参考，不自动等同于无误差的 3D 模型。

**摄影取景（必需，非可选）**：

- 3D 中清晰区分 **观察模式**（手指随意旋转模型）与 **相机模式**（固定并预览真正要输出的画面）。
- 相机模式提供画面取景框、平移/环绕/升降、俯仰与水平角度、距离/缩放、透视/正交切换及焦距或视角（FOV）。手机端用少量直接控件和触控操作，不暴露相机矩阵。
- 常用机位预设：正面、侧面、45°、俯视、低机位；可保存自定义镜头。提供画幅和比例（例如竖版、横版、方形）。
- 可锁定姿势只调整相机；也可锁定相机再调整姿势，便于比较。同一相机参数必须用于 RGB、Depth、Normal、Pose 等输出，并与最终 2D 画幅对齐。
- **不把“换一个视角由 AI 猜图”当作真实 3D 相机**；若以后接入 ComfyUI 多角度图生图节点，应清楚标注这与同一模型的真实几何投影不同。

**送往 2D**：一键发送选定姿势、相机及控制参考图；由 2D 用匹配的生成模型、ControlNet 或其他参考控制完成衣服、质感、画风与细节。ControlNet 尚未实际接通，不宣称精确复制任何结构。

**人物预览**：默认有基本皮肤材质的正常表面，支持切换白模、轮廓线/骨架作为检查模式；不追求在 3D 中先把最终画面全部做好。

## 服装设计：未来的小功能（已登记，当前不做）

用户**不需要学习打版、剪裁或手工制作服装**。预期流程：

1. **导入服装图片**：用户给服装照片/插画，指定想保留的款型与颜色。
2. **AI 辅助解析**：识别上衣、裙摆、袖子、领口、配饰、层次、配色等；提出可编辑的款式拆分。这里的“分解”先指视觉结构理解，**不能承诺单张图片自动得到准确的工业纸样或可穿戴 3D 网格**。
3. **AI 修改 + 用户验收**：用户说“这里短一些 / 改面料 / 调开口 / 增加装饰”，系统生成清楚的修改预览；用户满意并确认后才进入下一步。
4. **穿到角色上**：以后将已批准的款式转为可贴合基础模特的低复杂度服装，调整位置、基础布料下垂和碰撞，再通过 2D 完成最终观感。
5. **素材能力有限时降级**：优先少量基础版型和常用材质；复杂服装可只保留图像参考给 2D，不因 3D 换装能力不足阻塞出图。

**明确延期**：现在不安装/学习完整 Marvelous Designer，不开发全自动布料模拟、工业级打版、庞大材质库或复杂服装生成模型。它是未来可接入 3D 的小功能，由总控展示和记录设计确认，3D 负责可穿戴结构（如实现），2D 负责视觉成图。第三方参考素材仍应核对许可与访问权限。

## 使用方式

- **AI 辅助**：用户描述想法，AI 在已授权能力范围内执行并展示可核查的结果。
- **用户手动调整**：以拖拽、预设与少量滑条为主，专业参数按需展开。

不是两个软件、两个版本，也不复制两份作品库。

## 实际状态

- **已有**：2D 基础开发代码与示意 UI；3D 文档、导出 schema 和静态/独立预览实验。
- **未完成**：统一启动器、真实可编辑人体预览器、真实相机出图、3D 与 2D 的 ControlNet 闭环、服装图片解析/换装。
- 当前阶段先验证 2D 出图，再建立 3D **姿势 + 相机** 与 2D 的最小闭环；服装只做待办登记，不占当前开发时间。

## 新增需求备忘｜2026-11-09（仅记录，暂不开发）

> 本节记录用户本轮提出的产品体验方向，不代表技术方案已定稿、已连接 ComfyUI、已建模或已经通过实测。暂不编写代码，也不改变现有的“先实现 2D / 3D 姿势相机闭环”的阶段优先级。

### 一、按元素复用与局部编辑

- 用户希望直接用自然中文说明意图，不亲自写提示词或操作 ComfyUI 节点；AI 助手负责将用户选择映射到模型、参考图、遮罩、参数和工作流。
- 一幅作品的**人物身份/面貌、体型、姿势、构图/相机、衣装、表情、背景、画风**可分别引用来源、保存为预设、重组使用；允许用户认可某张作品的构图或身材后单独保存，不必锁死整张成图。
- 典型例子：保留图 A 的人物、使用写真 B 的姿势、另选衣装、背景由 AI 生成；先固定人物和姿势，之后按局部逐次替换衣服、脸部表情、背景或灯光。
- 不将自动分析一张图所得比例/机位冒称准确参数；源图只给出 2D 线索，无法唯一恢复隐藏身体形状、真实镜头和遮挡结构。每类参考需说明用途、约束强度及可能漂移的部分。

### 二、体型及构图：轻量三维中间层

- 设独立的**体型预设**与**构图/镜头预设**：体型侧重肩胸腰臀、四肢长度及大轮廓；构图侧重相机角度、画幅、裁切、距离、人物在画面中的位置。姿势单独存储，避免和相机绑定死。
- 推荐用**曲线连续、参数可调但不过度精细的 3D 人体预览模型**调整体型/姿势，再由真实相机统一输出结构控制图。它是 2D 成图的辅助，不追求完整物理、高精纹理和复杂衣服。
- 已有精美 2D 成图只想微调脸、服装、背景等时，优先局部重绘；若要大改姿势、比例和透视，优先返回 3D 中间层再生成。不要要求用户每次都重建全套 3D。

### 三、独立「衣装」资源模块

- 衣装不从属于某个固定人物：支持角色原装/专属衣装、可复用的公共晚礼服、日常服装等分类与混搭。用户可上传服装图片、收藏衣装方案、单独更换与局部调整，保留人物面貌和姿势。
- 每套衣装记录来源、适用角色、是否通用、可见部件/配饰和授权状况；私人购入素材不得默认进入公开库、自动训练或再分发资源。
- **优先通过 2D 参考图 + 遮罩局部重绘换装**；仅在需要姿势遮挡和构图支撑时使用简化 3D 衣装。单张服装图不能保证复原背面或真实裁片。
- 本模块先纳入 UI/需求备忘；衣装照片拆解、可编辑 3D 换装和复杂布料模拟均**暂缓实现**。

### 四、成图后的一键「动态」微动画

- 用户不需要制作复杂动画或手动摆关键帧。希望 2D 图片生成后，可一键尝试自动分层、补齐遮挡、建立轻量骨骼/网格，并启用眨眼、呼吸、头发摆动、胸部轻晃、腰臀轻摆等**小幅循环预设**。
- UI 保持简单：动作开关、幅度、速度、循环播放、预览和导出（GIF/MP4）；不默认向用户显示骨骼编辑器、时间轴或专业节点。
- 技术说明：**生成的 PNG 并不天然自带骨骼**；自动分层/绑定需要独立后处理，具体动作仍需形变参数或预设姿态，只是不要求用户制作关键帧。复杂遮挡、交叠饰物、衣装会导致失败，应允许显示待修复部位或退回静态图。
- 此功能属于 2D 的**可选后处理模块**，可借鉴 Live2D/Spine 的分层网格和物理约束，但不直接宣称生成原生 Live2D/Spine 工程，也不提前承诺兼容所有图片。

### 五、项目边界与实施顺序

- 继续采用三仓库架构：**总控管理 UI、预设、素材和作品；3D 提供体型/姿势/相机/结构导出；2D 负责参考生成、局部修图和未来微动画后处理**。
- 用户当前只要求**记录**，不写代码、不建立新功能、不扩大当前软件开发范围；这些属于以后逐步细化的备忘，不覆盖现有里程碑。
- 保存预设时明确区分：用户亲自认可的结果、AI 自动提取的候选参数、待验证假设和实际测试通过的功能。对原始素材保持只读，尊重来源和许可。


## 产品决策补充｜2026-11-09：双核心、精选动作与可升级架构

**目标**：幻真画室有两个并列而非主次的用途：（A）RTX 3060 Ti 本地尽量在 2–5 分钟内生成一张精美动漫角色插画（时间为待测目标，不能保证）；（B）独立欣赏可旋转的精致成年人体 3D 模型，观察体型、自然表面、姿势与镜头，可切换白模/基础材质/衣装。3D 不得降格为只导出骨骼图的工具；但 2D 生图不应被每次强制启动 3D 所拖慢。

### 动作资源：精选、分类、插值
- 先清点用户已有白模、带骨骼模型、动作 ZIP 与购买资源，按站姿/坐跪/俯身支撑/躺卧等少量分类，去重后每类保留约 2–3 个用户认可的动作；原始文件只读，精选预设另存。
- 同骨架或完成重定向后的相近姿势允许关节插值生成数秒 3D 片段，需处理脚滑、关节极限、穿模与局部网格塌陷；跨度大的姿势不保证自动自然过渡。
- 可叠加少量局部微动作：眨眼、呼吸、头发/配饰摆动、胸廓与软组织局部形变。3D 可使用骨骼、形态键和约束；2D 需分层、网格绑定、补画遮挡。开关/幅度/速度/循环即可，不要求用户操作专业时间轴。支持静帧与 GIF/MP4 导出作为未来目标。
- 3D 骨骼经相机投影可初始化 2D 关节位置，但不能凭此恢复成图的像素图层、头发眼睑或真实隐藏结构；采用一套 3D 主骨架 + 多种 2D 形变模板，必要时纯图像绑定降级。

### 实现与性能边界
- 3D 优先复用 Blender、现有连续人体网格和合法授权的模型/动作，不从零开发建模内核；交互预览可考虑 Three.js，Blender 负责姿势、形变、结构图导出。高质量离线渲染可选，实时查看必须流畅。
- 2D 由 ComfyUI 负责生成、参考控制、局部重绘、放大；首先以用户认可的两张精美动漫壁纸作为审美验收参考，分别检查透视姿势和礼服/材质光影。RTX 3060 Ti 8GB 下需实测工作流时间、显存与画质，不能先承诺达标。
- 主程序/2D/3D 维持三个 GitHub 仓库；衣装、动作、动画、素材、作品、更新机制均先做仓库内模块，不新建仓库。大文件存 D 盘，保留来源、授权和原始压缩包。
- 为未来局部升级预留版本化接口：角色/体型/姿势/镜头/衣装/动画预设独立存储，模型适配器可替换，升级前备份，失败可回退；不保证不同 AI 模型或骨架零成本兼容。

### 素材盘点与补充顺序
1. **先验现有资产**：可编辑且连续的成年人体 .blend/.fbx/.glb、骨架/权重、体型形态键、已有白模和动作、动画格式与许可。已有不代表已经验证兼容。
2. **优先补缺口**：同骨架的 A/B 相近姿势对（便于插值）、3–5 张不同角度的人体/服装参考、眼睑开合及表情差分、可分层的头发/衣装小样、基础皮肤/织物/金属材质小样。
3. **动画参考**：若用户之后下载 NIKKE/Spine 资源，检查 .skel/.json/.atlas/分层贴图、网格权重与动作；普通截图/GIF 只能观察视觉效果，不能推断工程骨骼。不要把第三方素材直接上传公开仓库。
4. **暂不需要**：海量姿势包、重复人体白模、整套电影级渲染资产、大量教程视频、完整物理布料系统。先做一个模型、两组相近姿势、一种局部形变、一条 3D→2D 出图闭环。

**状态说明**：以上均为需求与技术候选，尚未进行本地安装、解压、模型兼容性检查或性能实测。


## 界面方向备忘｜2026-11-11：常驻模特与三种自适应状态（用户认可，仍待原型验证）

> **设计探索记录，不是最终 UI 定稿或已实现功能。** 用户希望摆脱生硬方框和工业软件界面，借鉴游戏角色展示的沉浸感，但取景更接近私人写真摄影棚，而非游戏摄影模式。

### 总体组织
- **一个持续存在的成年女性 3D 模特实例 + 三种工作状态 + 八类共享元素**；模式是交互布局，不是三个独立场景或独立数据集。切换时不重置人物、体型、姿势、表情、衣装。
- 八类元素 C 人物、B 身材、P 姿势、O 衣装、E 表情、K 镜头、G 场景/场景构图、S 画风是“操作对象”；三种状态是“当前任务”。元素不锁死在某一状态。
- **人物状态**：模特占据主要画面，可自由观察，重点调用 C/B/P/E，直接点选身体/面部后出现相关工具。
- **搭配状态**：模特缩至一侧但仍可旋转/交互；重点展示 O 和相关材质、资源卡，减少与当前任务无关的模型工具。
- **写真状态**：保留当前模特/姿势/衣装，切换真实虚拟相机的取景体验；重点 K/G/S，可调用 P/E。摄影棚氛围、构图和试拍优先，不以密集 FOV/矩阵等工业参数为主界面。
- **沉浸/独处视图**是随时可开启的显示开关，不是第四个编辑模式；隐藏工具和资源卡，保留人物、环境、基础旋转缩放。强调私人空间与人物连续感，不引入游戏任务、抽卡或等级系统。

### 交互和过渡候选
- 观察与编辑分开：拖动空白处或视口环绕观察、单击人物/部位选中、明确进入编辑后才修改，避免误触；双指/滚轮缩放平移。具体手势待测试。
- 根据当前选中对象呈现少量**上下文工具**，不用固定摆满八类面板；复杂素材库/作品管理仍可使用清晰的普通列表界面，不强行塞进 3D 空间。
- 人物→搭配：视角拉远/模特偏移，衣装卡浮现；搭配→人物：卡片收起并恢复原观察视角；任意→写真：过渡至摄影相机并显示取景框；写真→人物：恢复自由观察相机。**观察相机和写真相机分别保存，不相互覆盖**。
- 模特远近由视口布局/相机与 LOD 控制，不修改其真实体型或重建模型；放大时恢复较高细节。
- 色彩方向可探索雾紫蓝、珍珠白、柔和深蓝摄影棚，避免大面积生硬工业框；最终视觉效果以原型实测为准。

### 待验证问题
1. 模特缩小后仍能方便交互，尤其手机/平板和 Windows。
2. 八类元素如何以少量可发现的入口切换，不产生两套菜单。
3. 3D 写真取景与 2D 画布如何衔接，同时保留相机/人物状态。
4. 状态切换动画的速度、镜头连续性和性能；不能让动画过渡妨碍日常操作。

**下一步建议**：先做可点击的三状态 UI 原型，验证真实体验后再定稿；不改变现有 2D/3D 实机验收优先级。


## 当前优先 UI 方案｜2026-11-11：房间即界面、家具即功能（取代上节抽象三状态导航）

> **已获用户认可的体验方向，尚未实现；交互细节仍可讨论。** 本节在 UI 导航方式上优先于前文“四个主入口”“三状态按钮/标签”的旧设想；前文保留为历史探索和功能需求，不代表仍需显示四个主按钮。此处只定义用户体验和画面，不要求用户决策技术架构。

### 一、整体空间与氛围
- 整个应用的主界面就是一间**华丽但克制的私人写真工作室**，尽量不用工业软件面板和生硬方框；以真实空间、镜头移动和家具交互作为导航。
- 房间中心是一位**可独立交互的成年女性 3D 模特**。默认地面考虑大面积、质感精致的香槟/象牙色短绒丝绒地毯或柔软地垫，要求模特站立、坐下、跪坐、躺卧都不显突兀；材质与色彩待视觉样图确认。
- 起步只放**模特、大衣柜、大摄影机**三个核心交互对象，不为八类元素分别添加八件家具；后续新功能可通过新增家具/空间物件进入，但不为扩展而堆满房间。
- 房间、家具外观、材质、装饰与氛围图优先使用 AI 生成的**可替换视觉素材**；用户提出“换个房间/衣柜/摄影机/地毯”时，重点是换外观、保持入口和交互不变。视觉上大致协调即可，不要求所有家具都做电影级精细建模；需要旋转/遮挡/点击的部分保留必要空间表现。**可换图片不等于任意视角的真实 3D 结构。**
- 模特的独立观察与姿势、表情、体型调整是核心体验，不因环境采用轻量素材而弱化。

### 二、三个实体入口与共享八元素
| 房间实体 | 点击后的画面变化 | 主要元素 | 核心交互 |
| --- | --- | --- | --- |
| 模特 | 镜头聚焦模特、人物放大；家具弱化/暂时退出视野 | C 人物、B 身材、P 姿势、E 表情 | 旋转观察、选姿势、调体型、调表情 |
| 大衣柜 | 镜头转向模特与衣柜的组合构图；模特相对缩小但可交互 | O 衣装 | **一侧单件分类，一侧整套分类**；单独取用、整套换装、组合预览 |
| 大摄影机 | 镜头转向摄影机并进入写真取景/2D 创作视图；模特和当前穿搭不重置 | K 镜头、G 场景/构图、S 画风；按需调用 P/E | 调机位、构图、试拍、生成和查看 2D 作品 |

- **八元素是素材与操作对象，不是八个顶级页面。** 元素可以跨入口调用，例如摄影时微调表情、换衣时旋转模特。
- 用户可把人物/体型/姿势/衣装/表情/镜头/背景/画风分别保存为元素预设并组合；衣柜对应衣装资源的实体化浏览，作品和素材库仍需方便查找，不强制把所有文件列表摆在房间里。
- **同一模特与同一作品状态贯穿房间、衣柜和摄影机**。不因切换功能而重置姿势、衣装、表情、体型。

### 三、独立观察（极简、纯模特）
- 从模特进入独立观察后，**连房间、家具、地面/地毯都隐藏**，画面只保留模特和极少量必要按钮；鼠标拖动可观察角度，支持缩放。
- 点击模特身上的衣装可临时隐藏其显示以查看身体；**隐藏不是删除或永久脱衣状态变更**，退出后可恢复原穿着。
- 此状态以欣赏与直接观察为主，**不在里面开放完整编辑工具**；想调整姿势、表情、衣装等须退出返回对应功能。
- 退出按钮必须清楚、数量尽量少。退出后恢复进入前的房间/人物观察上下文；是否保留独立观察最后的角度待原型测试。

### 四、模式之间的镜头与导航（尚待比较）
- 进入功能时不硬切换到完全陌生的页面，而是**镜头转向相应家具及模特**，家具成为操作入口和视觉语境。人物状态放大模特，衣柜状态保留模特+衣柜，摄影状态以模特+摄影机/取景为主。
- 待验证的两种退出/切换方式：
  1. 一个常驻但低存在感的**返回房间**按钮；回到能看到家具的总览。
  2. 功能内提供一个**极简空间导航入口**，可直接选择其他家具，让镜头转过去，不必先回房间。
- 优先避免屏幕常驻一整排“人物/衣柜/摄影机/八元素”标签；可以考虑在镜头适当拉远时点击真实家具直接切换，或用极小的临时导航。
- 摄影模式既是 3D 真实取景，也是进入 2D 生图的自然桥梁；**生成后如何回看、修改、返回摄影棚**，需单独设计，不能让生成结果把原 3D 模特状态覆盖。
- 观察相机与写真相机的视角各自保留，减少往返时的跳变；视觉过渡应柔和但不能拖慢操作。

### 五、视觉与资源更新原则（用户已明确）
- 用户主要通过自然语言表达“换地毯/换房间/换衣柜/换风格”，由 AI 生成候选图片并用于替换视觉素材；用户主要评判**好不好看、交互是否自然**，不承担编程/维护技术决策。
- 房间与家具**视觉素材可换、功能入口不变**。家具的交互职责、元素类别、人物状态不因外观换皮而改变。
- 追求华丽、柔和、私密的写真空间，而非机械、游戏任务或工业软件风格；“写真摄影”而非游戏摄影模式。图像素材与真实可交互模特的呈现质量可以分级。
- 软件尚未形成上述可运行 UI；目前只是产品交互记录，不能将图像概念图视为已经具备功能。

### 六、待讨论的 UX 决策（不问用户代码）
1. **从衣柜/摄影模式如何直接看见并点击其他家具？** 只留一个“返回房间”入口，还是加极简的家具快捷切换？
2. **衣柜内部如何呈现两侧分类？** 真正打开衣柜门、抽屉与挂架，还是衣柜作为背景、资源卡片浮现？如何在小屏/横屏中保持模特可见？
3. **点击模特时如何区分“观察、选身体部位、进入独立观察”？** 尽量不引入大量按钮与误触。
4. **摄影机进入 2D 后，生成作品、再次修改、回到 3D 的连续体验**：是取景框内显示成图、旁边展开作品墙，还是摄影机旁的相册？
5. **衣装点击隐藏的粒度与恢复规则**：点击整套/单件、是否允许连续隐藏多件、退出时自动恢复，待实测。
6. **地毯与模特躺卧的接触感**：需要验证接触阴影、地面高度、镜头角度与布料视觉是否自然。

**当前建议的第一轮原型**：一间房、一位模特、一只大衣柜、一台摄影机，演示从房间分别进入人物/衣柜/摄影与独立观察，验证镜头过渡和返回方式。此阶段不扩展新家具，也不要求用户理解实现细节。


### 导航方案确认｜2026-11-11：微缩房间与固定机位

**用户已明确选择**：以一个小型**虚拟房间缩略图**作为跨功能导航。点击缩略图内的模特、衣柜、摄影机或房间位置，主视口相机沿平滑路径移动至相应的**预设机位**，无需每次先退出功能回到总览，也无需传统多级菜单。可做成微缩立体房间，具体外观待样图确认。

- 房间缩略图是低存在感的导航控件；默认可见于普通功能界面，位置和展开方式待原型验证；点击房间整体可回全景。
- **固定机位是进入功能时的默认构图，不是锁死视角**：进入后仍可按该功能允许的方式观察/微调；可考虑保存离开时的视角，返回时恢复。此恢复策略尚待实测。
- 转场以镜头平滑平移/环绕至目标为主，避免硬切屏和繁复过场动画；人物、姿势、衣装、表情状态不变。
- **独立观察**是例外：隐藏微缩房间、家具和地面，仅显示模特与最少的退出按钮；退出后恢复进入前上下文。
- 本方案替代前节“返回房间按钮或家具快捷菜单二选一”的未定讨论，优先实现为**缩略房间直接导航**。如小屏幕上缩略图遮挡内容，可做轻量收起/展开，但不改变导航隐喻。
- 本次仅更新 UX 记录，尚未制作或验证可运行界面。


### 衣柜交互方案确认｜2026-11-11：双开门外观、左右分类、画册陈列

**用户认可，待视觉原型验证**：
- 房间里的衣柜是一件华丽但直观的**双开门家具**；点击后镜头平滑转到**衣柜 + 模特**的构图，模特保持可见、可旋转与试穿预览。
- **左柜：单件服饰，按种类分类**（上衣、裙装、袜饰、配件等）；**右柜：完整套装，按风格分类**（宫廷、礼服、日常、幻想等）。具体类别可按资源量调整。
- 视觉上**外观像真实衣柜，内部用精美画册/图片陈列**，不要求真的逐件从衣架取下。柜门、边框、柔和灯光提供空间感；图片和简洁分类提供易用性。
- 选中服饰后立即在模特上预览；选择整套后仍允许从左柜替换其中某件、保存新搭配。衣柜上可提供低存在感的搜索入口，支持按服装名称、材质、颜色或风格检索。
- 优先保证**模特与衣柜同时可见**；衣柜内部左右分区不等于主屏必须各占一半。避免密集方格和复杂多层菜单。
- 服装外观图片、衣柜外观可独立替换；分类、试穿与保存行为保持一致。此为交互设计确认，不表示自动 3D 换装已经实现。


### 摄影机体验方向｜2026-11-11：低门槛拍照与 2D 生图

**用户要求**：不熟悉摄影，交互尽量简单、功能够用即可；重点是将 3D 人物、姿势和真实镜头构图协调传递到 2D，连接本地 ComfyUI；对于适用且符合政策的普通图像，也希望可选择使用 ChatGPT 的图像生成能力。

- **点击房间里的摄影机** → 主镜头平滑转入写真取景状态，保留当前人物、身材、姿势、表情、衣装。取景时以直接拖动、旋转、缩放为主，不要求用户理解 FOV、焦距、相机矩阵等术语。
- **拍照** → 当前真实 3D 取景形成构图/姿势参考 → 交给 2D 生图 → 在摄影界面查看结果；可保存、重拍、用自然语言要求局部修改。3D 原始状态与生成结果分别保留，方便返回修改姿势或机位。
- **主界面按钮尽量少**：核心为取景、拍照/生成、查看结果；画幅可用竖/方/横三个直观选项，其他设置按需展开。避免把 ComfyUI 节点、摄影参数和提示词编辑器作为用户必经操作。
- **生成路径**：本地 ComfyUI 为计划中的主要闭环；ChatGPT 图像生成是可用且合规时的辅助路径。两者不是同一个模型，也不能未经验证就宣称 ChatGPT 生图可由独立软件直接调用；是否可自动切换、可调用的接口/权限、构图一致性与质量均需实际验证。
- **暂不扩大摄影功能**：不做专业摄影控制台、复杂灯光面板或大量镜头参数预设。优先完成“3D 调姿势与机位 → 2D 出图 → 结果预览与修改”的易用闭环。
- **状态**：需求已记录，UI/接口尚未实现和验收。
