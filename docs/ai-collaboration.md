# AI 协作｜接手与维护

更新：2026-11-11。供 ChatGPT、Grok 或其他工具接手同一项目，不预设某工具具备特定功能。用户通过自然语言与视觉结果验收，正式文档使用正常技术文风。

## 接手顺序

1. 先读[首页](../README.md)与[开发状态](roadmap.md)，确认仓库、真实进展和未验证项。
2. 做体验设计时读[产品体验](product-ux.md)；素材读[元素与素材](element-library.md)；近期衣装读[衣装方案](clothing-plan.md)。
3. 修改模块前读[职责](responsibilities.md)和[接口](integration.md)，再核对当前代码、资产和运行记录。
4. 动画、姿势与软组织文档是专题研究，不自动变成当前阶段的全部需求。

主仓库：[Fantasy-Studio](https://github.com/Xiatiantian1997/Fantasy-Studio)。三个仓库的职责已在专门文档维护，不为每个 AI 复制一套介绍。

## 文档维护规则

- 同一主题只维护一份当前规则；其他文件用链接引用，不追加多份近义描述。
- 用户后续明确确认的决定替换旧方案；历史通过 Git 查看。真实冲突无法判断时保留待确认项，不擅自取消需求。
- 分清**已确认需求、候选方案、已写代码、实测通过**。不能把概念图、静态 HTML、schema、README 宣称或未验证素材说成已实现。
- “衣装当前不做动画/连续适配”只限定衣装近期范围，不取消整个产品的长期动画/体型方向。
- 核对当前仓库名称、链接和可见性，不沿用旧的 Fantasy-Studio- 名称或把总控默认当私人仓库。
- 交付说明实际改动、验证结果与未完成事项；用户没有要求实现时，不顺手安装模型、搬移资产或扩展功能。
- 保留原代码与用户资产；文档整理不改变已有 API、schema、模型文件或测试结果。

## 协作和外部交接

通过版本化 JSON、模型/动作文件和本地 API 交换数据，不要求工具共享账户或文件系统。角色、体型、姿势、镜头、衣装与动画参数分开保存。外部文件记录来源、许可、适用骨架、版本和验证状态；未经用户确认不发送给第三方服务。

用户决定素材来源、保存位置、授权和对外分享；各工具在自身能力与适用规则内工作，不预设其他服务支持任何特定内容。

## 公开与私人资料

- 公开仓库只保存通用代码、文档及允许再分发的演示；私人原图、付费素材原档、大模型、真实私有索引和配置留本地。
- 统一索引记录文件 ID、原路径/派生路径、来源、访问范围、用途与许可；私人资产不混入公共示例、未授权搜索结果或日志。
- AI 只读取已授权输入；“用户手动可访问”和“默认代理可访问”可不同，但不需要两套软件或重复原档。
- 目录隐藏不等于权限隔离；需要实际访问控制、排除规则和备份。
- 参考、训练、再分发分别核对许可。涉及年龄的资料保留依据与不确定项，年龄未知不能自行当作成年；未成年人不得进入成人参考处理池。
- Git 提交历史仍可查看；改写当前文件不等于清除历史中的私人信息。

## 评审关注点

评审应提出具体问题、依据和最小验证步骤，重点检查：

- 总控接入现有 2D 是否破坏原来的开发与回归入口；
- 房间切换是否保留模型、衣装、表情与两类相机状态；
- 结构包版本、坐标、分辨率和 ControlNet 输入是否匹配；
- 实际人体、衣服、姿势的适配质量，而不是只看文件扩展名；
- Windows 上 Blender、ComfyUI 与分析模型的资源占用；
- 统一索引的权限、来源、版本、恢复和路径迁移；
- 哪些是近期可验收的小闭环，哪些是长期研究。

评审或交接说明引用上述当前文件，不重新复制全部计划。
